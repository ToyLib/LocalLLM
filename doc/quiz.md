# クイズタブ

分野を選ぶと 10 問 (4 択) を出題し、最後に点数とねぎらいのメッセージを出すタブです。
ローカルの LLM に問題を作らせ、採点はアプリが機械的に行います。
設計の経緯は [quiz-plan.md](quiz-plan.md) にあります。C++ 版 (ImGui) と Python 版 (Tk) の両方にあります。

## 画面

ウィンドウはタブ (C++ 版は `ImGui::BeginTabBar`、Python 版は `ttk.Notebook`) で、「チャット」タブ (今までの画面) と「クイズ」タブを切り替えます。
どちらも裏で動き続けるので、切り替えても会話もクイズの途中経過も消えません。

| 状態 | 内容 |
| --- | --- |
| 分野の選択 | 分野の選択欄、開始ボタン、注意書き |
| 出題中 | 進み具合 (Q3 / 10) と正解数、問題、4 つの選択肢、回答 / 次の問題へ / やめる、正誤と解説 |
| 結果 | 点数、ねぎらいのメッセージ、間違えた問題の見直し、もう一度 / 分野を変える |

## 分野

最初から 4 つあります。`config/quiz.json` の `categories` に足せば、コードを変えずに分野を増やせます。

| 分野 | `source` | 内容 |
| --- | --- | --- |
| プログラミング | `llm` | プログラミングの基礎 (言語に偏らない) |
| IT パスポート試験 | `llm` | ストラテジ系・マネジメント系・テクノロジ系の基本用語 |
| 一般常識 | `llm` | 日本の社会人として知っておきたい一般常識 |
| 資料から出題 (rag/) | `rag` | `rag/` の資料の内容 ([rag.md](rag.md)) |

- `llm` の分野は、モデルの知識から出題します。**小さなモデルは、誤った正解や解説を作ることがあります** (特に IT パスポートのような用語の細部)。画面に注意書きを出しています。
- `rag` の分野は、インデックスのチャンクを 1 つずつ渡して出題させるので、正解が必ず資料に載っています。解説に出典 (資料名と見出し) を出します。一番信頼できる分野です。資料の読み込みが終わっていないときは、始められません (エラーを出します)。

## 自作の分野

「分野を編集…」から、自分のお題で出題する分野を作れます (Python 版、C++ 版とも。保存先は共通なので、どちらで作った分野ももう一方で使えます)。
設定ファイルを開かずに、画面の中で作る・直す・消すができます。

| 項目 | 内容 |
| --- | --- |
| 分野名 | 分野の選択欄に「名前 (自作)」と出る |
| お題・出題の方針 | 自由に書く。例: 「Git のブランチとマージ。初心者向けに、コマンドの意味を中心に」 |
| 資料 (rag/) を使う | オンにすると、資料から出題する |
| ChatGPT で出題する | オンにすると、出題をローカルの LLM ではなくクラウド (`server.json` の `cloud`) に頼む |

- 保存先は、設定フォルダーの `quiz_custom.json` です。同梱の `quiz.json` とは分けてあるので、更新や「設定を既定値に戻す」で消えません。形式は `{"categories": [{"name": ..., "prompt": ..., "use_rag": ..., "use_cloud": ...}]}` です。
- 問題の形式 (4 択・正解・解説) の指示は `generate_prompt` のままで、お題は「出題範囲」として足すだけです。書き換えても形式は壊れません。
- 「資料を使う」がオフなら、お題から**出題のトピックを先に作らせ** (`topics_prompt`、1 回の呼び出し)、1 問ごとに 1 つずつ割り当てます。作れなかったときは、既出の問題を渡す方式だけで進めます。
- 「資料を使う」がオンで、お題が空なら、資料からランダムに選びます (「資料から出題」と同じ)。お題があれば、**お題に近い資料から**近い順に選び、お題を「出題の方針」として添えます。類似度の下限は設けないので、関連する資料が少ないと、あまり関係のない部分から出ることがあります。
- 「ChatGPT で出題する」は、小さなローカルのモデルが苦手なお題 (細かい知識や専門用語) の誤りを減らすためのものです。出題とトピック作りの呼び出しだけをクラウドに送り、ねぎらいのひと言はローカルのままです。API キーが無いときは、テスト出題や開始のときにエラーを出します。利用料がかかります。
- **「資料を使う」とは同時にオンにできません。** `rag/` の資料を外に送らないためです (一方をオンにすると、もう一方は選べなくなります)。ファイルを直接書き換えて両方 `true` にしても、資料を使う側が優先され、クラウドには送りません。
- 「テスト出題」で、保存前に 1 問だけ作って、お題の効き具合を確かめられます。小さなモデルは書き方で出来が変わります。
- 名前が空、または「お題が空で資料も使わない」分野は保存できません。`quiz_custom.json` が壊れているときは、上書きして中身を消さないよう、編集できません (エラーを出します)。

## 動き

1. 「開始」で、別スレッドが**問題を 1 問ずつ**作り続けます。10 問を 1 回で作らせると、長くて遅く、小さなモデルでは形式が崩れるためです。ユーザーが解いている間に、次の問題が用意されます。追いついたときは「次の問題を準備中…」を出します。
2. 問題は JSON スキーマで、`question` (問題文)、`correct` (正解の文)、`wrong` (誤りの文 3 つ)、`explanation` (解説) を出させます。正解の番号ではなく文で受け取るのは、小さなモデルが番号を 1 始まりで答えたり、解説の番号とずれたりするためです。選択肢はアプリが並べ替え、正解の位置を覚えておきます (`quiz_mode.validate_question`)。
3. 選択肢が重複している・空のときなど、形が正しくなければ、3 回までやり直します。それでも作れない問題は飛ばして、出題数を減らします。1 問も作れなければ、分野の選択に戻ってエラーを出します。
4. 10 問の重複を避けるため、`llm` の分野は `topics` から重複なしで 1 問ごとに割り当て (足りなければ循環)、既出の問題文を次の出題に渡します。`rag` の分野は、重複なしで別々のチャンクを選びます。資料が少なければ、出題数をチャンクの数まで減らします。
5. 答えると、すぐに正誤と解説を出します。
6. 最後の問題のあと、点数と、正解率の帯 (100% / 80% / 50% / それ以下) ごとの**固定のメッセージ**をすぐ出します。続けて、回答役の人格 (`comment_persona`) の口調で、点数を踏まえたひと言を LLM に作らせ、できたら置き換えます (失敗したら固定のメッセージのまま)。
7. 結果の画面で、間違えた問題を、自分の答え・正解・解説つきで見直せます。

成績は保存しません (起動中だけ)。「やめる」を押すと、その回は破棄して分野の選択に戻ります。

## 設定 (config/quiz.json)

| キー | 内容 | 既定値 |
| --- | --- | --- |
| `question_count` | 出題数 | 10 |
| `max_tokens` | 1 問を作るときの最大トークン数 | 1024 |
| `comment_persona` | ねぎらいの口調に使う回答役 (`agents.json` のキー。`assistant` か `general`)。空にすると固定のメッセージだけ | `assistant` |
| `generate_prompt` | 出題の system プロンプト (文字列か、文字列の配列) | (ファイル参照) |
| `topics_prompt` | 自作の分野で、お題からトピックを作らせる system プロンプト | (ファイル参照) |
| `results` | 正解率の下限 (`min_percent`) とメッセージ (`text`) の一覧 | (ファイル参照) |
| `categories` | 分野の一覧 (`key` / `name` / `source`、`llm` の分野は `guide` と `topics`) | (ファイル参照) |

正しくない項目は既定値になります。

**注意**: 設定ファイルの既定値 (`config/`) は、ユーザーごとのフォルダーに**無いときだけ**コピーされます ([config.md](config.md))。`quiz.json` を直したあと、すでにコピー済みの環境には反映されません。設定のフォルダーの `quiz.json` を消すか、設定を既定値に戻してください。

## 作りの要点

- `quiz_mode.py` (C++ 版は `quiz_mode.cpp`) は画面を知らない。`QuizState` (ロックで守った状態と、画面を起こす `notify`) を、ワーカースレッドが書き、UI スレッドが読む。
- 開始・やめるたびに `session` を増やし、古いワーカーが新しい回に書き込まないようにしている (中断用のトークンも回ごとに作る)。
- `quiz_ui.py` の `QuizTab` は、自分で `after` を回して描画する。チャット画面の `_poll` / `_refresh` とは独立している。
- 小さなモデルでも崩れないよう、出力は `llama-server` の JSON スキーマで形を制限している ([agent.md](agent.md) のルーターと同じ仕組み)。

## C++ 版との違い

| 項目 | Python 版 | C++ 版 |
| --- | --- | --- |
| ファイル | `quiz_mode.py` / `quiz_ui.py` | `quiz_mode.cpp` / `quiz_ui.cpp` (`QuizState` が状態) |
| 中断用のトークン | 回ごとに `CancelToken` を作る | 回ごとに `std::shared_ptr<std::atomic<bool>>` を作り、ワーカーにも持たせる |
| 回の切り替え | 古いワーカーは `session` の違いで書き込みを諦める | 同じ。さらに、開始・やめるときに古いワーカーの終了を待つ (`StopWorkers`) |
| 資料のチャンク | `rag.sample_chunks` / `rag.top_chunks` | `SampleRagChunks` / `TopRagChunks` (文字数は UTF-8 のコードポイントで数える) |
| 分野の編集画面 | 選択画面の代わりに出す `ttk.Frame` | 選択画面の代わりに描く (`DrawEditor`)。入力欄は `ImGui::InputText` で分野のデータを直接書き換える |
| テスト出題 | ワーカースレッドが結果を `QuizTab` の変数に書く | `QuizState` の `testWorker` / `testResult` (mutex で守る)。開始・止めるたびに前のスレッドの終了を待つ |
| 選択肢 | ラジオボタン (折り返し付き) | ラジオボタンの横に折り返した文を並べ、文のクリックでも選べる |
| 状態の更新 | `QuizTab` が自分で `after` を回す | ワーカーから `WakeUI()` で起こす |
