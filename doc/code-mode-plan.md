# コーディング練習タブの設計メモ

プロンプトからコードを作り、解説を読み、実行して、少し自分で手を入れて試せるタブを足すための方針です。
バイブコーディングを、ローカル LLM で気軽に体験できるようにするのが狙いです。
まだ実装していません。

## 1. 方針

教育目的に絞りますが、クイズや課題のようなカリキュラムは作りません。LLM と実行環境だけで完結する大きさにとどめます。

| 区分 | 内容 |
| --- | --- |
| 今回 | プロンプトからコードを生成する |
| 今回 | コードの解説を表示する |
| 今回 | コードを実行して結果を表示する |
| 今回 | ユーザーがコードを編集して再実行できる |
| 後回し | HTML / JS のプレビュー、エラーの自動修正ループ、ステップ実行 |
| やらない | クイズ、課題、レベル別の教材 |

- 言語は Python だけにします。
- まず Python 版 (Tk) で作り、固まってから C++ 版に同じ設計で移します。

## 2. 画面

今のチャット画面は作り変えず、タブの 1 枚として残します。

```
root
└ ttk.Notebook
   ├ タブ「チャット」          … 今の画面そのまま
   └ タブ「コーディング練習」  … 新規 (CodeTab)
```

コーディング練習タブの中身は次のとおりです。

```
┌ 作りたいもの ──────────────────┐
│ 「1〜100のFizzBuzzを出して」     │ [作る]
├ コード (編集可) ─┬ 解説 ───────┤
│ for i in ...      │ 全体の流れ…  │
│ ...               │ 行ごとの説明 │
├ 実行結果 ─────────┴─────────────┤
│ 1 2 Fizz 4 Buzz ...              │ [実行] [停止] [元に戻す]
└──────────────────────────────────┘
```

- 切り替えても、会話も生成中のコードも消えません。両タブとも裏で動き続けます。
- `llama-server` の状態を出すサーバーバーは、タブの外に出して両タブで見えるようにします。
- 色とフォントは `ui.json` を両タブで共通に読みます。

## 3. 動き

1. 「作る」で、プロンプトからコードを 1 ブロック生成する (システムプロンプトで「Python のコード 1 ブロックだけ」と縛る)。コード欄にストリーミングで表示する。
2. コードが確定したら、そのコードを渡して**別の LLM 呼び出し**で解説を作る。
3. 「実行」で、確認のうえサブプロセスで実行し、stdout / stderr を表示する。
4. コード欄は編集できる。「元に戻す」で生成直後のコードに戻せる。編集後は「解説を作り直す」を押すと、いまのコードで解説を作り直す。

### 生成と解説を分ける理由

1 回で両方を出させると、小型モデルは形式が崩れやすくなります。コードを確定させてから解説を作れば、コードと解説がずれません。

### 解説の形

全体の流れを 2〜3 文で書き、そのあとに重要な部分だけ「N 行目: …」で補足します。
全行を説明させると長くなるうえ、小型モデルは行番号を間違えやすいためです。
設定でオンにすると、解説を回答役の口調 (`personas.json`) で書かせます。

## 4. 実行の安全

LLM が書いたコードを実行するので、次を守ります。

- 実行は必ず確認ボタン式にする。コードを見てから押す。自動実行はしない。
- 専用の作業フォルダを cwd にする。
- タイムアウト (既定 10 秒) と出力サイズの上限を付ける。
- 環境変数は最小限だけ渡す。ChatGPT の API キーなど (`secrets.json`) をコードから見えないようにする。
- コンテナなどの本格的なサンドボックスは初版では入れない。画面に「自己責任」の注意書きを出す。

## 5. ファイル

| ファイル | 内容 |
| --- | --- |
| `python/code_mode.py` | 生成、コードブロックの抽出、解説の生成、サブプロセス実行 (`llm_client.ask_llm` を再利用) |
| `python/code_ui.py` | コーディング練習タブ (`CodeTab`) |
| `python/chat_ui.py` | 部品の親を `root` から `ttk.Frame` に替え、`Notebook` に載せる |
| `config/code.json` | タイムアウト、生成用と解説用のシステムプロンプト、モデル指定、人格の使用 |
| `doc/code-mode.md` | 実装後の説明 (このメモは設計メモとして残す) |

- コード向けのモデルを割り当てられるよう、ルーターや回答役とは独立にモデルを選べるようにします。
- `ChatApp` の `_poll` / `_refresh` はチャット画面専用のままにします。`CodeTab` は自分で描画し、タブが非表示でも壊れないようにします。

## 6. 進め方

1. チャット画面を `Notebook` の 1 タブに載せ替える。見た目と動作が変わらないことを確認する。
2. コーディング練習タブを足す (生成 → 解説 → 実行 → 編集)。
3. 手順書と `doc/code-mode.md` を書く。
4. Python 版で固まってから、C++ 版に移す。
