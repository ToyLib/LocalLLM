# データの行き先 (プライバシー)

`rag/` の資料や会話は個人的な内容を含むことがあるので、どのデータがどこへ送られ、どこに残るかをまとめたメモです。
**資料 (`rag/`) の内容は、ChatGPT などのクラウドには送りません。**
ChatGPT に送る内容の決め方は [chatgpt.md](chatgpt.md#送る内容-資料を守るために) と [chatgpt-plan.md](chatgpt-plan.md) にも書いています。

## 送り先ごとの内容

既定の設定 (`server.json` の URL が `127.0.0.1`) の場合です。

| 送り先 | いつ | 送るもの |
| --- | --- | --- |
| チャット用サーバー (ローカル 8080) | 質問のたび | ルーター: 資料の一覧 (ファイル名と見出し)、直前の会話 (最大 4 件、1 件 300 バイトまで)、質問 |
| | | 回答役: system プロンプト、それまでの会話 (聞き直して置き換えた回答を除く)、質問 (資料を使うなら、資料の抜き出しを添えたもの) |
| | 聞き直しで書き直すとき | 回答役の system プロンプト、書き直しの指示、最新の質問、ChatGPT の回答 |
| | 聞き直した後、違いをまとめるとき | 違いのまとめの指示、最新の質問、聞き直す前のローカルの回答、ChatGPT の回答 (それぞれ先頭の一部) |
| 埋め込み用サーバー (ローカル 8081) | インデックスを作るとき | `rag/` の資料の全文 (チャンクに分けたもの。変わったファイルだけ) |
| | 資料を検索するとき | 質問 |
| ChatGPT (OpenAI、https) | 「ChatGPT に聞き直す」を押したときだけ | ChatGPT 用の system プロンプト、資料を使っていない過去のやりとり、最新の質問 |
| | 「Web でも調べて比べる」を押したときだけ (設定でオンのとき。資料を使った回答では出さない) | ChatGPT 用の system プロンプト、資料を使っていない過去のやりとり、最新の質問。OpenAI がこれをもとに検索語を作って Web を検索する |

このほか、ファイルの取得のために次の場所へ接続します。質問や資料は送りません。

| 接続先 | いつ | 取得するもの |
| --- | --- | --- |
| GitHub (llama.cpp のリリース) | C++ 版のビルド時。Python 版は `llama-server` が見つからないときの初回の起動時 | `llama-server` の公式リリース |
| Hugging Face | `llama-server` が、まだ手元に無いモデルを起動するとき | モデル (GGUF) |

### ChatGPT に送らないもの

- 資料を使って答えたやりとり (質問も回答も)。資料を使った回答は、ChatGPT に聞き直せません (ボタンを押せなくしています)
- ルーターに渡す資料の一覧 (ファイル名と見出し)
- 聞き直す前のローカルの回答 (聞き直したら履歴から外れる)
- 回答役の system プロンプト (ChatGPT には `agents.json` の `cloud` のプロンプトを送る)
- API キー以外の設定、`rag/` のファイルそのもの

ルーターと RAG の検索は、いつもローカルで行います。ChatGPT に何かを送るのは、ユーザーがボタンを押したときだけです。
出典の URL を開くのは、ユーザーがクリックしたときだけです (http / https の URL だけを開きます)。

## 手元に残るもの

| 場所 | 中身 | 消し方 |
| --- | --- | --- |
| `build/rag-index.json` (C++ 版)、`python/rag-index.json` (Python 版) | 資料のチャンクの**本文**と、そのベクトル | ファイルを消す (次の起動で作り直す) |
| `build/rag/` | `rag/` のコピー (ビルドのたびに置き換え) | `build/` ごと消す |
| ユーザーごとのフォルダーの `config/` | 設定 (サーバーの URL や system プロンプトなど) | 設定画面の「すべて既定に戻す」、またはフォルダーを消す |
| 秘密ファイル (`secrets.json`) | API キー (macOS / Linux は `0600`) | 設定画面の「秘密ファイルから削除」、またはファイルを消す |
| アプリのログ (標準エラー) | 検索のたびの類似度と、資料のファイル名・見出し。アプリは質問や回答の本文、API キーを出さない | — |
| llama-server のログ (アプリが起動したときはユーザーごとのフォルダーの `logs/`、起動スクリプトのときはチャット用は端末、埋め込み用はリポジトリの `logs/embed-server.log`) | 何を出すかは llama-server のバージョンや起動オプション次第 (詳しいログを有効にすると、送った文章が含まれることがある) | `logs/` を消す |
| 会話 | メモリーの中だけ (保存しない)。アプリを閉じるか「クリア」で消える | — |

- `rag/` は `samples/` と `README.md` 以外を `.gitignore` で除外しています。インデックス (`rag-index.json`) も git に入りません。
- `build/` を zip などで人に渡すと、`build/rag/` とインデックスに資料の中身が含まれます。

## API キーの扱い

- キーの値は設定ファイルに書かず、環境変数か秘密ファイルから読みます。設定ファイルのフォルダー (リポジトリの `config/`、ユーザーごとのフォルダーの `config/`) には置きません。
- https の URL のときだけ送ります。`cloud.chat_url` を `http://` にすると、キーを送らずにエラーにします。
- 画面には末尾 4 文字だけを出し、ログやエラーメッセージにはキーやリクエストのヘッダーを出しません。
- おすすめのキーの作り方 (専用プロジェクト、マシンごとのキー、利用上限) は [chatgpt.md](chatgpt.md#キーの作り方のおすすめ) を参照してください。

## 設定を変えるときの注意

- `server.json` の `chat_url` / `embed_url` を別のマシンにすると、上の表の「ローカル」の内容 (資料の全文を含む) がすべてそのマシンに送られます。http のままなら暗号化もされません。
- `cloud.chat_url` を別のサービスにすると、聞き直したときの内容と API キーがそのサービスに送られます。
- 回答役の `rewrite` を false にしても、ChatGPT に送る内容は変わりません (書き直しをローカルで行うかどうかだけが変わります)。
