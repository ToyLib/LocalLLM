# RAG (資料を参照した回答)

`rag/` フォルダに置いた `.md` / `.txt` から質問に近い部分を探し、参考資料として質問に添えて LLM に送ります。
LLM が知らない個人的なメモや手元の資料についても、資料に基づいて答えられるようになります。

## 動かし方

チャット用のサーバー (8080 番) に加えて、埋め込み用のサーバーを 8081 番で使います。
llama-server の起動スクリプトが、両方をまとめて起動します。

| OS | スクリプト |
| --- | --- |
| Linux | [scripts/llama-server-linux.sh](../scripts/llama-server-linux.sh) |
| macOS | [scripts/llama-server-macos.sh](../scripts/llama-server-macos.sh) |
| Windows | [scripts/llama-server-windows.ps1](../scripts/llama-server-windows.ps1) |

```bash
./scripts/llama-server-macos.sh
```

- メニューでモデルを選ぶと、埋め込み用のサーバーを裏で起動してから、チャット用のサーバーを手前で起動します。
- 埋め込み用のサーバーのログは `logs/embed-server.log` に出ます (Windows は標準エラーが `logs/embed-server.err.log`)。
- チャット用のサーバーを Ctrl+C で止めると、埋め込み用のサーバーも一緒に止まります。
- 埋め込み用のサーバーがすぐに終了した場合 (8081 番が使用中など) は、ログの末尾を表示して、チャット用のサーバーを起動せずに止まります。
- RAG を使わないときは `--no-embed` (Windows は `-NoEmbed`) を付けると、チャット用のサーバーだけを起動します。

埋め込みモデルは多言語に対応した BGE-M3 (`ggml-org/bge-m3-Q8_0-GGUF`、約 600 MB) です。初回起動時に自動でダウンロードされます。

アプリを起動すると、画面上部に `6 ファイル / 54 チャンク` のようにインデックスの状態が表示されます。
「資料 (RAG)」は既定で「自動」になっていて、ルーターエージェントが質問ごとに資料を参照するかを決めます ([説明](agent.md))。
「常に」にすると毎回資料を参照し、「使わない」にすると資料を添えずに質問します (RAG の効果を比べるときに使えます)。

サンプルで試せる質問の例:

- ミケのおやつは 1 日何本まで？
- ノリの朝ごはんは何グラム？
- ミケの好きな食べ物は？ / ノリのお気に入りの場所は？
- ノリにかつお節をあげていい？ (好物のメモとダイエット中のごはんのメモの両方が関係する質問)
- ミケの薬を朝に飲ませ忘れたらどうする？
- 日曜日の夜に猫の具合が悪くなったらどこに連れて行けばいい？
- ダイエット中の猫の目標体重は？ (プロフィールとごはんのメモの両方が関係する質問)
- 次のワクチンはいつ？ / 歯石取りに保険は使える？ (健康と通院の記録)
- 爪切りのコツは？ / ブラシはどこにある？ (お世話の日課とグッズ)
- ノリの名前の由来は？ / クリスマスツリーが小さいのはなぜ？ (うちの子になった日とエピソード)
- 冬にミケが見当たらない (好きな場所のメモと事件簿の両方が関係する質問)

回答の下には、参照した資料と類似度が表示されます。

## しくみ

```
[起動時 / 再読込ボタン]  (rag.cpp: BuildIndex)
  rag/ の .md / .txt を集める
    → 前回と内容 (ハッシュ) が同じファイルは、保存済みのチャンクを使い回す
    → 変わったファイルだけ、400 文字以内のチャンクに分ける
       (.md は見出しごとに段落をまとめ、.txt は段落ごとに分ける)
    → 埋め込みサーバーでベクトルにする (16 チャンクずつ)
    → build/rag-index.json に保存

[質問のたび]  (chat.cpp: SendPrompt → rag.cpp: SearchRag)
  (「自動」のときは、先にルーターが資料を参照するかを決める)
  質問をベクトルにする
    → 全チャンクとのコサイン類似度を計算 (総当たり)
    → 類似度 0.5 以上の上位 3 件を、資料として送信する質問の前に付ける
    → いつもどおり AskLLM でストリーミング受信
```

- 資料は**送信する質問にだけ**付けます。画面の履歴 (`ChatState::messages`) には元の質問だけが残るので、会話が資料で膨らみません。
- 埋め込みサーバーにつながらないときやインデックスが無いときは、回答の下にその旨を表示して、資料なしで回答を続けます。
- インデックスの作成は専用のスレッドで行うので、作成中もチャットは使えます。
- 検索のたびに上位 5 件の類似度をログ (標準エラー) に出します。`MIN_SCORE` を調整するときの参考にしてください。

## 文書の置き場所

| 場所 | 説明 |
| --- | --- |
| `rag/` (ソースツリー) | ここに文書を置きます。`samples/` と `README.md` 以外は `.gitignore` で除外されます |
| `build/rag/` | ビルドのたびに `rag/` の内容で置き換えられます (`sync_rag` ターゲット) |
| `build/rag-index.json` | 埋め込み済みのインデックス。消すと次回起動時に作り直します |

文書を追加・編集・削除したら、もう一度ビルドしてから、アプリを起動し直すか「再読込」を押してください。
ビルドせずに別のフォルダを使いたいときは、環境変数 `LOCALLLM_RAG_DIR` で指定します。

```bash
LOCALLLM_RAG_DIR=~/Documents/notes ./build/LocalLLM
```

- 対象は `.md` / `.markdown` / `.txt` です。UTF-8 でないファイル (Shift_JIS など) は読み飛ばし、ログに出します。
- 名前が `.` で始まるファイルやフォルダ、`rag/` の直下の `README.md` は対象外です。

## 設定

| 項目 | 場所 |
| --- | --- |
| 埋め込みサーバーの URL | `src/llm_client.cpp` の `EMBED_URL` |
| チャンクの最大文字数 | `src/rag.cpp` の `MAX_CHUNK_CHARS` (変えたら `INDEX_VERSION` を上げる) |
| 添える資料の数 | `src/rag.cpp` の `TOP_K` |
| 類似度の下限 | `src/rag.cpp` の `MIN_SCORE` |
| 資料の添え方 (指示文) | `src/rag.cpp` の `BuildRagPrompt` |

埋め込みモデルを別のものに変えたときは、`build/rag-index.json` を消してインデックスを作り直してください。
